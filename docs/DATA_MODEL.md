# Data model

Everything the map draws comes from one JavaScript object literal near the top of the
`<script>` in `index.html`:

```js
const D = { days: [...], pois: [...], phases: [...], routes: [...], total: 2275, total_alt: 2255 };
```

It is valid JSON (the app never mutates it on disk), so tools can parse it with a simple
regex + `JSON.parse`. `tools/reroute.py` does exactly this. Keep it that way: **no
comments, functions, or trailing commas inside `D`.**

Unicode (°, ·, –, — and the non-breaking hyphen ‑ used in road names like `NM‑80`) is
stored literally. If you regenerate `D` from a script, dump with `ensure_ascii=False`.

---

## `days[]` — the itinerary (one per calendar day)

| Field | Type | Notes |
|---|---|---|
| `n` | int | Day number, 1-based. Used as the marker label and `data-n` on cards. |
| `date` | string | `"Thu Aug 6"` — weekday + month + day. The year (2026) is implied; `dayDate()` parses it. |
| `phase` | string | One of the `phases[].id` values. Drives the color. |
| `title` | string | Short leg title. |
| `lat`, `lon` | float | Overnight location. Days sharing a rounded lat/lon share one map marker. |
| `elev` | int | Feet. |
| `drive` | int | Miles for the day (planner's estimate). Shown in cards/table. |
| `drive_txt` | string | Human distance+time, e.g. `"379 mi · ~6 h 15 m"`. `dtime()` extracts the `~6 h 15 m` part. |
| `route` | string | Roads/turns description. |
| `hi`, `lo` | int | August climate **normals** °F. See [Weather](#weather). |
| `wx` | string | Weather prose. |
| `doing` | string[] | Activity list (mostly birding). Rendered in cards and the table's Leg cell. |
| `sleep` | string | Camp/lodging. |
| `flags` | string[] | Warnings; rendered red. May contain HTML (`⚠`, `<b>`). |
| `bike` | string | Riding notes; may be `""`. May contain HTML (the `★` day-pick markup). |

## `pois[]` — points of interest (markers you can toggle)

| Field | Type | Notes |
|---|---|---|
| `name` | string | Popup title + hover tooltip. |
| `lat`, `lon` | float | Location. |
| `elev` | int | Feet. |
| `phase` | string | Color (one of `phases[].id`). |
| `note` | string | Popup body. May contain HTML. |
| `kind` | string | **`"bird"`**, **`"bike"`**, or **`"other"`** — selects the marker shape *and* which toggle layer (`LG.bird` / `LG.bike` / `LG.other`) it joins. |
| `day` | string | Free-text day hint like `"Day 6 (Tue)"`, or `""`. |

Marker shapes: `bird` = open circle in phase color; `bike` = violet rounded square with a
bike glyph; `other` = small neutral square. This keeps layers distinguishable with color
turned off.

## `phases[]` — trip segments and their colors

| Field | Type | Notes |
|---|---|---|
| `id` | string | Referenced by `days[].phase` and `pois[].phase`. |
| `name` | string | Legend label. |
| `light`, `dark` | string | Hex color for each theme. Injected into CSS as `--p-<id>`; read by `pc(id)`. |

## `routes[]` — the drawn polylines

| Field | Type | Notes |
|---|---|---|
| `pts` | [lat, lon][] | Vertices in **[lat, lon]** order (Leaflet order). Regenerated by `tools/reroute.py`. |
| `mi` | int | Listed miles (planner's estimate; shown in the tooltip label). |
| `phase` | string | Color. |
| `style` | string | `"solid"` (main route) or `"dash"` (side trip / alternate). |
| `label` | string | Tooltip text, e.g. `"Day 9 · Madera Canyon → Patagonia · 65 mi"`. |
| `road_mi` | float | *Added by `reroute.py`.* Actual road distance of `pts`. Absent if the leg kept its hand-drawn points. Used by `mileFlag()`. |

`total` / `total_alt` are the trip mileage figures shown in the header and the table
footer; they are **not** recomputed from `routes` and are left as planner's numbers.

## Weather

Built-in `days[].hi` / `days[].lo` are **August climate normals** — always present, so the
map is useful offline and far in advance.

At runtime, `enrichForecasts()` (bottom of the script) tries to overlay a **live NWS
forecast** on any day whose date is within ~7.5 days of *now*:

1. `GET https://api.weather.gov/points/{lat},{lon}` → `.properties.forecast` (a gridpoint URL).
2. `GET` that URL → `.properties.periods[]`, each with `startTime`, `isDaytime`,
   `temperature`.
3. For the target date: the daytime period's temp = high, the night period's = low.

On success the day gets a runtime-only `d.fc = { hi, lo, asOf }`, the card temp cell and
the marker popup are patched, and the value is labeled **"forecast"**. Any failure
(offline, out of horizon, API error) is swallowed per-day and the normals stand. Results
are cached per rounded lat/lon so shared locations fetch once.

`wxTemps(day)` / `wxLabel(day)` are the single place that decides "forecast vs normals"
for display — read those first if you touch weather rendering.
